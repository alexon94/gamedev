# Создание 2D-игры в Godot: практический путь

Этот документ описывает полный цикл создания небольшой 2D-игры в Godot: от идеи и GDD до тестирования, сборки под Android и публикации в браузере.

## 1. Что понадобится

### Основная программа

**Godot** — игровой движок, в котором создаются сцены, уровни, персонажи, логика, физика, анимации, интерфейс, звук и сборки игры.

### Дополнительные программы

Они не все нужны сразу. Устанавливайте их по мере появления соответствующей задачи.

| Программа | Для чего используется | Обязательность |
|---|---|---|
| Krita | Рисование персонажей, фонов, интерфейса и текстур | По необходимости |
| Aseprite | Пиксельная графика и покадровые sprite-анимации | По необходимости |
| Blender | 3D-модели, анимации, рендеры и подготовка 3D-ассетов | Только для 3D |
| Audacity | Запись и обработка звуковых эффектов | По необходимости |
| LMMS или Bosca Ceoil | Создание музыки | По необходимости |
| Figma | Проектирование интерфейсов и экранов | По желанию |
| Tiled | Создание tilemap-карт и уровней | По желанию; в Godot есть собственный TileMap |
| VS Code | Альтернативный редактор кода | Не нужен новичку |
| Git и GitHub Desktop | История изменений, резервные копии и совместная работа | Очень рекомендуется |
| Android Studio | Android SDK, подключение телефона и Android-сборка | Нужна при экспорте на Android |

### Минимальный бесплатный набор

Для старта достаточно:

1. Godot.
2. Krita или Aseprite.
3. Audacity.
4. GitHub Desktop.
5. Android Studio — когда понадобится сборка под Android.

На первых этапах можно использовать временные изображения, звуки и бесплатные ассеты. Сначала проверяйте игровой процесс, а потом заменяйте временные материалы финальными.

## 2. Этап 0: идея и границы проекта

До открытия Godot сформулируйте игру в нескольких предложениях.

Ответьте на вопросы:

- Кто игрок?
- Что он делает большую часть времени?
- Какова главная цель?
- Что мешает ему её достичь?
- Почему игроку будет интересно продолжать?
- На каких устройствах будет игра?
- Какой минимальный объём игры можно закончить за 2–8 недель?

Для первой игры лучше выбрать один небольшой жанр:

- платформер на 3–5 уровней;
- top-down аркаду;
- головоломку;
- кликер;
- игру на уклонение;
- простой tower defense.

Не стоит начинать с большой RPG, MMO, онлайн-игры или проекта с открытым миром.

## 3. GDD — Game Design Document

GDD — это короткое описание игры, которое помогает не потерять цель проекта. Для первой игры это не обязательно большой документ: достаточно 1–5 страниц.

### Рекомендуемая структура GDD

#### 3.1. Общая информация

- рабочее название;
- жанр;
- целевые платформы;
- аудитория;
- одно предложение, описывающее игру;
- референсы и примеры похожих игр.

#### 3.2. Игровой цикл

Опишите повторяющуюся последовательность действий игрока. Например:

```text
исследовать уровень → найти врага → уклониться или атаковать → получить награду → открыть следующий участок
```

Если игровой цикл непонятен, проект ещё слишком плохо сформулирован.

#### 3.3. Управление

Опишите действия для каждой платформы:

| Действие | Клавиатура | Сенсорный экран |
|---|---|---|
| Движение | A/D или стрелки | виртуальный джойстик |
| Прыжок | Space | кнопка прыжка |
| Атака | ЛКМ или Ctrl | кнопка атаки |
| Пауза | Esc | кнопка меню |

#### 3.4. Механики

Опишите правила игры:

- здоровье;
- урон;
- противники;
- предметы;
- очки;
- уровни;
- победа и поражение;
- сохранение прогресса.

#### 3.5. Визуальный стиль

- пиксель-арт или рисованная графика;
- разрешение и соотношение сторон;
- основные цвета;
- вид камеры;
- примеры персонажей и окружения.

#### 3.6. Объём первой версии

Зафиксируйте, что обязательно входит в первую версию, а что откладывается.

Пример MVP:

- один персонаж;
- один тип врага;
- один уровень;
- одна основная механика;
- экран победы;
- экран поражения;
- базовой звук.

## 4. Этап 1: подготовка проекта Godot

1. Создайте новый проект.
2. Выберите подходящий рендерер. Для простой 2D-игры обычно достаточно Compatibility.
3. Создайте папки проекта:

```text
project/
├─ scenes/
├─ scripts/
├─ art/
│  ├─ characters/
│  ├─ environment/
│  └─ ui/
├─ audio/
│  ├─ music/
│  └─ sfx/
├─ data/
└─ docs/
```

4. Назначьте главную сцену.
5. Включите контроль версий Git.
6. Зафиксируйте первую рабочую версию проекта.

### Именование

Используйте понятные имена:

- `player.tscn` — сцена игрока;
- `player.gd` — скрипт игрока;
- `level_01.tscn` — первый уровень;
- `enemy_slime.tscn` — сцена конкретного врага;
- `ui_hud.tscn` — игровой интерфейс.

Не называйте файлы вроде `new_new_final2.tscn`.

## 5. Этап 2: прототип

Прототип проверяет, интересна ли основная механика. Используйте простые квадраты, круги и временные изображения.

В прототипе должны появиться:

- движение игрока;
- основное действие — прыжок, стрельба, сбор предметов или уклонение;
- хотя бы одно препятствие или один враг;
- условие победы;
- условие поражения;
- возможность перезапустить игру.

Цель прототипа — не красота, а ответ на вопрос: интересно ли играть в это хотя бы несколько минут?

## 6. Этап 3: базовая архитектура Godot

Godot строится вокруг сцен и узлов.

Пример сцены игрока:

```text
Player (CharacterBody2D)
├─ Sprite2D или AnimatedSprite2D
├─ CollisionShape2D
├─ Camera2D
├─ AttackArea (Area2D)
└─ AnimationPlayer
```

Пример сцены уровня:

```text
Level01 (Node2D)
├─ TileMap
├─ Player
├─ Enemies
├─ Collectibles
├─ CameraLimits
└─ UI
```

Распределяйте ответственность:

- игрок отвечает за движение и действия игрока;
- враг отвечает за своё поведение;
- уровень отвечает за размещение объектов;
- UI отвечает за отображение состояния;
- отдельный менеджер отвечает за переходы между уровнями и глобальный прогресс.

Не помещайте всю игру в один огромный скрипт.

## 7. Этап 4: управление и физика

Сначала реализуйте управление на клавиатуре, затем добавьте сенсорные кнопки для Android.

Рекомендуется использовать Input Map в настройках Godot:

- `move_left`;
- `move_right`;
- `jump`;
- `attack`;
- `pause`.

Тогда одна игровая логика сможет работать с клавиатурой, геймпадом и сенсорным интерфейсом.

Проверяйте:

- скорость движения;
- ускорение и торможение;
- высоту прыжка;
- поведение на склонах и краях платформ;
- столкновения;
- работу на разных разрешениях.

## 8. Этап 5: графика, анимации и уровни

После проверки механики заменяйте временные объекты на настоящие ассеты.

### Графика

- создайте единый размер спрайтов;
- определите палитру и стиль;
- используйте одинаковую толщину контуров;
- храните исходники отдельно от экспортированных файлов;
- не перегружайте фон деталями, которые мешают видеть игрока.

### Анимации

Минимальный набор для персонажа:

- idle;
- run;
- jump;
- fall;
- attack;
- hurt;
- death.

### Уровни

Сначала делайте короткие уровни, где каждая новая механика появляется постепенно. Не добавляйте сразу все типы врагов и препятствий.

## 9. Этап 6: интерфейс, звук и обратная связь

Игрок должен понимать, что произошло.

Добавьте:

- здоровье;
- очки или валюту;
- индикатор цели;
- паузу;
- экран победы;
- экран поражения;
- подсказки в начале игры.

Для действий полезны:

- звук попадания;
- звук получения предмета;
- визуальная вспышка при уроне;
- частицы;
- небольшая вибрация на Android;
- изменение анимации персонажа.

## 10. Этап 7: тестирование

Тестируйте игру регулярно, а не только перед публикацией.

### Чек-лист

- можно ли начать игру с нуля;
- работают ли победа и поражение;
- не застревает ли игрок в стенах;
- нельзя ли пройти уровень обходом важных объектов;
- не ломается ли пауза;
- сохраняется ли прогресс;
- корректно ли масштабируется интерфейс;
- работает ли звук после потери фокуса;
- не слишком ли долго загружается игра;
- можно ли играть одной рукой на телефоне.

Проверяйте игру минимум на слабом Android-устройстве и на нескольких размерах экрана.

## 11. Этап 8: оптимизация

Сначала добейтесь работающей игры, затем оптимизируйте только реальные узкие места.

Основные меры:

- уменьшить размеры текстур;
- использовать атласы спрайтов;
- не создавать тысячи объектов без необходимости;
- удалять объекты, которые далеко за пределами камеры;
- сжимать аудио;
- уменьшать количество тяжёлых частиц;
- проверять FPS и время кадра встроенным профайлером Godot.

Оптимизируйте по измерениям, а не по догадкам.

## 12. Этап 9: экспорт на Android

1. Установите Android Studio и Android SDK.
2. Настройте пути к Java SDK и Android SDK в Godot.
3. Подключите телефон с включённой отладкой по USB.
4. Проверьте игру через запуск на устройстве.
5. Для теста экспортируйте APK.
6. Для Google Play подготовьте подписанный AAB.
7. Проверьте разрешения, имя пакета, иконки и ориентацию экрана.

Сохраните ключ подписи в безопасном месте. Потеря ключа может создать проблемы с обновлением опубликованной игры.

## 13. Этап 10: экспорт в браузер

1. Создайте Web/HTML5-пресет в Godot.
2. Проверьте управление мышью и клавиатурой.
3. Добавьте сенсорное управление, если игра должна работать на телефоне в браузере.
4. Проверьте размер загрузки.
5. Запустите сборку через локальный сервер.
6. Загрузите файлы на itch.io, Yandex Games, CrazyGames, Poki или собственный сайт.

В браузере особенно важны быстрый старт, небольшой размер файлов и корректное масштабирование под разные экраны.

## 14. Этап 11: публикация

Подготовьте:

- название;
- иконку;
- короткое и полное описание;
- скриншоты;
- трейлер или GIF;
- возрастной рейтинг;
- политику конфиденциальности, если есть аналитика, реклама или аккаунты;
- контакт разработчика;
- страницу поддержки.

Для Android основная площадка — Google Play. Дополнительно можно рассмотреть RuStore, Huawei AppGallery, VK Play и другие магазины.

Для браузера подходят itch.io, Yandex Games, CrazyGames, Poki, Newgrounds, Game Jolt и собственный сайт.

## 15. Best practices

### Делайте MVP

Сначала создайте минимальную завершённую версию. Лучше закончить игру с одним уровнем, чем год строить огромный проект.

### Используйте GDD как живой документ

GDD можно изменять, но каждое изменение должно быть осознанным. Если новая идея не улучшает основную игру, добавьте её в список будущих возможностей.

### Прототипируйте до создания финальной графики

Не тратьте недели на персонажа, пока не проверили механику его движения и взаимодействия.

### Делайте вертикальный срез

Вертикальный срез — небольшой, но почти законченный фрагмент игры: уровень, интерфейс, звук, враг, победа и поражение. Он показывает, как будет выглядеть весь проект.

### Храните проект в Git

Делайте коммиты после значимых изменений:

```text
Добавлено движение игрока
Добавлен первый уровень
Добавлены враги
Добавлено сохранение
Подготовлена Android-сборка
```

### Делайте частые сборки

Регулярно проверяйте игру на реальном телефоне и в браузере. Ошибки платформы лучше обнаруживать в начале, а не перед публикацией.

### Не смешивайте данные и логику без необходимости

Параметры врагов, предметов и уровней удобно хранить отдельно: в ресурсах Godot, JSON или других data-файлах. Так баланс можно менять без переписывания всей логики.

### Учитывайте мобильные устройства с самого начала

Проверяйте:

- размер кнопок;
- читаемость текста;
- работу одной рукой;
- паузу при сворачивании;
- разные соотношения сторон;
- производительность на слабом устройстве.

## 16. Рекомендуемый план первой игры

### Неделя 1: идея и прототип

- написать короткий GDD;
- настроить проект;
- сделать движение;
- добавить основную механику;
- создать простую победу и поражение.

### Неделя 2: игровой цикл

- добавить врага или препятствие;
- сделать один полноценный уровень;
- добавить UI;
- подключить временный звук;
- протестировать на телефоне.

### Неделя 3: контент и полировка

- заменить временную графику;
- добавить анимации;
- сделать эффекты;
- добавить второй и третий уровень;
- настроить баланс.

### Неделя 4: выпуск

- исправить ошибки;
- оптимизировать игру;
- подготовить иконки и скриншоты;
- собрать APK/AAB и веб-версию;
- опубликовать игру на выбранной площадке.

## Итог

Для обучения полному циклу геймдева оптимальный набор — **Godot + Krita/Aseprite + Audacity + Git**. Android Studio добавляется при подготовке Android-сборки, а Blender — только если проект требует 3D.

Главный принцип: маленький законченный проект даст больше опыта, чем большой незавершённый. Сначала создайте простую игру от идеи до публикации, а затем увеличивайте сложность.
