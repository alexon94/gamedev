# Путь разработчика игр: создание 2D-игры на Phaser

## 1. Что такое Phaser и чем он отличается от Godot

**Phaser** — JavaScript/TypeScript-фреймворк для 2D-игр, запускаемых в браузере. В Godot есть встроенный визуальный редактор сцен и уровней; в Phaser основная сборка и логика выполняются через код, а графика и карты могут готовиться в сторонних редакторах.

**Phaser особенно удобен**, если главная цель — веб-игра, которую затем можно опубликовать на игровых площадках. Для Android веб-игру обычно упаковывают в приложение через Capacitor/WebView. Godot лучше подходит, если хочется освоить полноценный визуальный игровой редактор и в будущем перейти к 3D.

## 2. Общая схема производства игры

1. **Идея и правила:** что делает игрок, как побеждает и проигрывает.
2. **Прототип:** простые геометрические фигуры вместо готовой графики, базовое управление и столкновения.
3. **Графика и звук:** спрайты, фоны, тайлсеты, анимации, эффекты.
4. **Уровни:** карты, препятствия, точки появления и выхода.
5. **Сборка в Phaser:** сцены, объекты, управление, физика, интерфейс, сохранения.
6. **Тестирование:** удобство управления, сложность, производительность, разные экраны.
7. **Публикация:** браузерная сборка; при необходимости Android-обёртка.

Этапы повторяются: после тестов часто приходится менять механику, карты и графику.

## 3. Программы и инструменты

| Инструмент | Назначение | Нужен сразу? |
|---|---|---|
| **VS Code** | Редактор кода | Да |
| **Node.js + npm** | Установка зависимостей и запуск проекта | Да |
| **Phaser** | Сцены, игровые объекты, ввод, анимации, физика | Да |
| **Vite** | Локальный сервер разработки и сборка | Рекомендуется |

| **Krita** | Рисованные персонажи, фоны, текстуры | По необходимости |

## 5. Как работают сцены Phaser

**Scene** — логическая часть игры: меню, игровой экран, экран результатов. Основные методы:

```ts
class GameScene extends Phaser.Scene {
  preload() {
    // Загрузка изображений, звуков, карт
  }

  create() {
    // Создание игрока, стен, ловушек и управления
  }

  update(time: number, delta: number) {
    // Обновление движения и игровой логики
  }
}
```

Для игры с десятками комнат лучше использовать **одну игровую сцену с загрузкой разных данных уровней**, а не писать отдельный класс для каждой комнаты.

## 6. Работа с графикой

### Пиксель-арт

Рисуется в Aseprite или LibreSprite. Экспортируется в PNG или spritesheet. Подходит для небольших персонажей, тайлов и анимаций.

### Рисованная 2D-графика

Создаётся в Krita. Подходит для более детализированных персонажей и фонов.

### Векторная и минималистичная графика

Создаётся в Inkscape, а иногда непосредственно в Phaser через геометрические примитивы. Для «100 смертельных комнат» это особенно практичный стиль: игрок — квадрат или круг, стены — прямоугольники, лазеры — линии.

### 3D-модели

Phaser не является полноценным 3D-движком. Blender можно использовать для создания 3D-моделей и рендеринга их в 2D-спрайты, но для первой 2D-игры это не требуется.

## 7. Создание персонажа

1. Нарисовать спрайт или временно использовать простую фигуру.
2. Загрузить изображение в `preload()`.
3. Создать игрока в `create()`.
4. Подключить клавиатуру и/или сенсорные кнопки.
5. Добавить скорость движения и столкновения.
6. При необходимости сделать анимации ожидания, движения и гибели.

Игрок должен быть отдельным переиспользуемым объектом, чтобы его логика не дублировалась в каждом уровне.

## 8. Создание уровней

### Вариант А: редактор Tiled

В Tiled можно рисовать пол и стены по сетке, размещать объекты, отмечать точки появления, выходы, ключи и ловушки. Карта экспортируется в формат, который может прочитать Phaser (например, JSON).

### Вариант Б: уровни в JSON

Для небольших комнат достаточно хранить координаты объектов:

```json
{
  "level": 1,
  "player": [2, 6],
  "exit": [8, 1],
  "walls": [[3, 4], [3, 5], [6, 2]],
  "lasers": [[5, 3]]
}
```

Код считывает данные и создаёт комнату. Это позволяет добавлять новые уровни без изменения основной игровой логики.

**Для первой версии:** начни с JSON и простых комнат. Tiled добавляй, когда ручное редактирование координат станет неудобным.

## 9. Управление, физика и столкновения

Phaser поддерживает клавиатуру, мышь, касания и контроллеры. Для простой аркады обычно достаточно **Arcade Physics**:

- движение по четырём направлениям;
- столкновение со стенами;
- обнаружение контакта с ловушкой;
- движение платформ и препятствий;
- мгновенный перезапуск после поражения.

Не каждому объекту нужна физика. Например, нажатие кнопки или проверку условия победы можно реализовать обычной логикой.

Для Android заранее продумай сенсорное управление: виртуальный джойстик, экранные стрелки или управление свайпами.

## 10. Анимации и визуальные эффекты

- **Sprite animations:** покадровая ходьба, гибель, движение врагов.
- **Tweens:** плавное открытие дверей, поворот лазеров, движение платформ, анимации интерфейса.
- **Particles:** искры, дым, вспышки.
- **Камера:** следование за игроком, тряска, масштабирование.

Для первой игры достаточно нескольких простых эффектов — главное, чтобы игрок понимал происходящее.

## 11. Звук, интерфейс и сохранения

В Phaser можно воспроизводить звуковые эффекты и музыку. Звуки можно подготовить в Audacity, музыку — в LMMS или взять из ресурсов с подходящей лицензией.

Интерфейс включает меню, паузу, номер уровня, счётчик попыток, таймер и экран победы. Для сохранения открытых уровней в браузере можно использовать `localStorage`, учитывая, что пользователь может очистить данные браузера.

## 12. Практический пример: «100 смертельных комнат»

**Цель:** добраться до выхода, не задев ловушки. Уровень занимает 10–30 секунд, при поражении мгновенно перезапускается.

**Минимальная версия (MVP):**

1. Один персонаж с движением по четырём направлениям.
2. Стены и столкновения.
3. Опасная зона, которая убивает игрока.
4. Выход, который завершает уровень.
5. Кнопка перезапуска.
6. Десять коротких комнат.
7. Простое меню выбора уровня.

**Первые десять уровней:**

| Уровень | Испытание |
|---|---|
| 1 | Прямой путь до выхода, обучение движению |
| 2 | Обход неподвижной стены |
| 3 | Первая неподвижная ловушка |
| 4 | Узкий коридор между опасными зонами |
| 5 | Движущийся лазер |
| 6 | Два лазера с разным ритмом |
| 7 | Кнопка, открывающая дверь |
| 8 | Исчезающий пол |
| 9 | Сочетание кнопки и движущегося лазера |
| 10 | Итоговая комната из нескольких изученных механик |

Хорошая последовательность сложности: **показать механику → дать потренироваться → соединить с другой → проверить навык**.

## 13. Тестирование

Проверяй:

- понятно ли управление без объяснений;
- не слишком ли мелкие элементы на телефоне;
- легко ли случайно задеть ловушку из-за неточного управления;
- быстро ли перезапускается уровень;
- корректно ли работает игра на разных размерах экранов;
- не падает ли частота кадров на слабых устройствах;
- сохраняется ли прогресс.

Для браузерной игры важно тестировать не только на компьютере, но и в мобильном браузере.

## 14. Публикация

### Браузер

Vite собирает проект в статические файлы HTML, JavaScript и ресурсы. Их можно разместить на хостинге или игровой площадке, например itch.io. Для конкретных платформ могут понадобиться их SDK, реклама, авторизация или другие интеграции.

### Android

Веб-версию можно упаковать через Capacitor/WebView. Для сборки Android-приложения обычно используют Android Studio. После упаковки необходимо отдельно проверить касания, ориентацию, полноэкранный режим, звук и производительность.

Это не нативный игровой экспорт в том же смысле, что у Godot: приложение запускает веб-контент внутри Android-оболочки.

## 15. Пошаговый путь обучения

**Этап 1 — основы:** JavaScript/TypeScript, создание проекта, запуск локального сервера, простая сцена.

**Этап 2 — управление:** персонаж, клавиатура, скорость движения, границы экрана.

**Этап 3 — столкновения:** стены, ловушки, смерть и перезапуск.

**Этап 4 — уровни:** данные JSON, переход между комнатами, первые 5–10 уровней.

**Этап 5 — оформление:** спрайты, анимации, звуки, меню, таймер.

**Этап 6 — мобильная версия:** сенсорное управление, адаптация под экран, тестирование.

**Этап 7 — публикация:** сборка браузерной версии, размещение, исправление ошибок по отзывам.

## 16. Phaser или Godot: что выбрать

| Критерий | Phaser | Godot |
|---|---|---|
| Главная среда разработки | Код и внешние редакторы | Встроенный визуальный редактор |
| Язык | JavaScript / TypeScript | GDScript / C# |
| Браузерные игры | Особенно удобен | Поддерживаются |
| Android | Обычно через веб-обёртку | Нативный экспорт |
| 2D-уровни | Tiled, JSON, код | Встроенный редактор |
| Переход к 3D | Не основное направление | Есть полноценные 3D-инструменты |
| Погружение в программирование веб-игр | Отлично | Не основная специализация |
| Погружение в работу с игровым редактором | Ограниченно | Отлично |

**Вывод:** если хочешь изучать визуальную сборку игр, сцены и редактор — Godot. Если хочешь научиться создавать браузерные 2D-игры с помощью JavaScript/TypeScript и гибко управлять всем через код — Phaser. Для «100 смертельных комнат» оба подходят.
